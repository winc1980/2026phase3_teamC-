# 詰まったときの進め方

## どんなときに読むもの？
実装していて「進まない」「何が起きているのか分からない」と思ったときに読んでください。

phase3で身につけてほしいのは、技術そのものより **詰まったときの進め方** です。困ったらこのページに戻ってきてください。

# 1.15分ルール

> **15分やって進まなかったら、人に聞いていい。むしろ聞いてください。**

3時間かけて自力で解決するのは、えらいことではありません。時間の使い方として損です。
ただし、いきなり聞くのも、メンターに丸投げになってしまって、学びにならないのでなしです。以下の順で進みます。

```
1. 切り分ける          本来どうなるはずのところで、どんなおかしなことが起きたのか。エラーは一応見る。何が吐いたエラーか、知ってる種類のエラーかどうかだけ分かればOK。ここでコードのどの行に対するエラーか読み取れれば、半分解決したようなもの。
2. 仮説を立てる          どこが怪しいか、分かる範囲で考える。心当たりがないか振り返ることに意味がある。経験したことがないトラブルだと、全然見当がつかないし、実際に訳の分からない理不尽な原因の時もある。そういう時は悩んでも仕方ないので4へ。
3. 怪しいところを見てみる 怪しそうなコード、エラー元になっているコードを見に行って、明らかな原因がないか探す
4. AIに聞く            ざっと見てよくわからなかったら、AIメンターに5点セットで聞く（AIを使っていない人は飛ばしてOK）
5. 15分たったら人に聞く  5点セットをそのままDiscordに貼る
```

**「自分の仮説」を書くのが一番大事です。** 外れてもかまいません。外れれば「そこじゃない」と分かるので、それも前進です。

聞く相手は、チームメイトか学習会メンターです。もくもく会なら口頭でもOKです。
Discordでは、そのタスクのフォーラムスレッドに貼っておくと、あとから同じところで詰まった人も読めます。


# 2.5点セット

少し書くのが面倒ですが、分からないことを自分で解決できるようになるための第一歩です。

```
1. やりたかったこと：

OOの機能を作ったのでXXが表示されるはずだった / OOの状態でXXのコマンドを打ったのでOOできるはずだった / XXのボタンを押すとOOの見た目になるはずだった

2. 実際に起きたこと：

XXにはOOしか表示されなかった / コマンドを打ったらXXというエラーが出た / XXのボタンを押したのに反応がない

3. エラーメッセージ（全文をコピペ）：

エラーがないときは省略で可。

4. 試したこと：

XXのOO行目って書いてあったのでそこを読んでみましたが、何が間違っているのかよくわかりませんでした。 / XXというエラーとは何か検索してみたけど、OOの時に出るらしいということ以外よくわかりませんでした。 / まず何をしたらいいのか全然わかりませんでした

5. 自分の予想（どこが怪しいと思うか）：

XX型の理解が曖昧なままコードを書いていたので、そこには自信がありません / 全然わかんないです

```

| | |
|---|---|
| **3のエラーは必ず全文** | 要約しないでください。長くても全部貼るのが結局一番早いです |
| **5が分からなくてもいい** | 「見当がつきません」でOK。書こうとしたこと自体に意味があります |
| **きれいに書かなくていい** | 箇条書きでも、単語だけでも通じます |


# 3.AIに聞くとき

AIメンターの準備は、[README](README.md#aiメンター) を見てください。

- **AIメンター設定（AI_mentor.md）を使っている場合、AIはトラブルシューティングの最初にこの5点を聞いてきます。** 先に揃えて渡せば、話が早く進みます
- **ChatGPTメンターは、GitHubに上がっているコードを読みます。** 手元だけで変更したコードは見えません。作業途中でもブランチをpushして、どのブランチかも伝えてから聞きましょう
- **AIの答えが、このプロジェクトの書き方と違うことがあります。** ファイル名やライブラリが違ったら、それを伝えて聞き直してください。同じずれが何度も起きるなら、AGENTS.md の「このプロジェクトの決まりごと」に書き足しておきましょう
- **15分たったら、AIとのやり取りの途中でも人に聞いてください。** 「AIにこう言われたけど動かない」は立派な質問です


# 4.やってはいけないこと

- ❌ **3時間ひとりで溶かす** — 15分で聞いてください
- ❌ **エラーを要約して貼る** — 全文を貼るのが結局一番早いです
- ❌ **完璧に理解してから進もうとする** — 分からないまま進んで、あとで戻ってくるのが普通です

---

**分からない場所が特定できたら、それはもう半分解決しています。**
